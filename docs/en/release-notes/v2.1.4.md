## v2.1.4 — Combat and anti-stuck (day 4)

- Added basic automatic attacks after approaching a living hostile NPC, with a configurable repeat interval.
- Added an approach deadline that persists across route recalculations. Failed routes and approach timeouts temporarily exclude that target so another mob can be selected.
- Added a combat progress timeout: a new lowest observed target HP resets the deadline. A stalled target is temporarily excluded; healing alone does not extend the deadline.
- Confirmed target death enters `Loot`; disappearance alone returns to target selection. Loot pickup remains day 5.
- Stop cancels pending bot command writes. Exiting combat requests movement to the hero's current position to interrupt the action. Death of the hero, loss of connection, or replacement of the hero session stops the engine; restarting requires Start.
- Updated Windows environment documentation and removed Finder metadata from the repository.

### Settings

Edit `config.json` and restart the client:

| Setting | Default | Meaning |
|---|---|---|
| `AttackIntervalSeconds` | 1 | Minimum interval between attack requests; checked on a 500 ms engine tick |
| `ApproachTimeoutSeconds` | 15 | Maximum time for one approach, including route recalculations |
| `CombatProgressTimeoutSeconds` | 20 | Maximum time without a new lowest observed target HP |
| `TargetCooldownSeconds` | 30 | Temporary exclusion after a route failure or timeout |

Intervals must be positive, finite, and no greater than 86400 seconds. Combat uses the existing `TargetSearchRadius` and `TargetApproachDistance`; this version provides basic attacks without skill rotations, automatic loot, potions, or rest.

### Validation and limits

Local Windows checks cover native regressions, targeting/movement, repeating attacks, HP progress, target death, cancellation during a pending attack write, disconnect, hero death, approach/combat timeouts, target exclusion and expiry, and the real C# to C++ named pipe protocol. The WPF client and Win32 DLL/Core also build locally. GitHub Actions repeats the checks before packaging this release.

Live Interlude validation is still required. Stopping sends an interruption request, but its in-game effect, structure offsets, hooks, and external pathfinding must be checked with the supported game client. Native pathfinding itself cannot be interrupted; cancelled searches send no new route after returning. Close the game to unload the injected runtime.

Download `L2Bot-win-x86.zip` under **Assets**, extract it, and run `Client.exe` on Windows. The client, DLLs, and 165 geodata regions are included.
