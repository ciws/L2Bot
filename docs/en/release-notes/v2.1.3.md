## v2.1.3 — Connection and runtime fixes

- Fixed the pipe handshake: the client strips the newline from the server's pipe name. Client writes are serialized and complete messages are assembled before parsing.
- Fixed `Invalidate` command formatting and reconnect synchronization. Each session starts with cleared client state and a fresh full snapshot, with the hero sent first. Event-driven skill, item, and buff caches are preserved during resync; duplicate creates update existing entities.
- Fixed JSON escaping for names, chat, descriptions, and field names.
- Corrected the thread enumeration structure size and process filter used while installing hooks.
- Replaced ineffective repository locks with a shared reentrant world-state lock covering snapshots and event updates. Skill cooldown/cast deadlines no longer use background timer threads, and other creatures' casts no longer mark the hero's skills busy.
- Fixed soulshot autouse disabling, update detection, and equipment type checks.
- Added client buff models, processing, and a Buffs tab. Inventory now distinguishes consumables, armor, weapons, and shields, refreshes updated descriptions/counts, and supplies the adena summary.
- Fixed superseded movement retries, disposed removed map/target subscriptions, bounded chat history, and surfaced connection startup errors.
- Kept the injected runtime loaded for the lifetime of the game session. DLL detach no longer waits for a worker under the Windows loader lock; hook trampolines use executable memory and flush the instruction cache.

### Validation

Native regression checks cover escaping, autouse, full snapshot replay, and synchronization. Real C# commands are passed through the production C++ parser and command dispatcher. Windows CI also exercises the actual named pipe handshake, repeated resync, reconnect, and shutdown, then builds the x86 DLL and WPF client.

Live Interlude validation is still required: game structure offsets and five-byte hooks remain specific to the supported client. Close the game to unload the injected runtime. Automatic combat is still the next roadmap step; this release does not add attacks.

Download `L2Bot-win-x86.zip` under **Assets**. Extract it and run `Client.exe` on Windows; the client, DLLs, and 165 geodata regions are included.
